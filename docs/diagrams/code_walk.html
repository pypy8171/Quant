TRADE 모드 · 틱 하나가 주문이 되고 원장·DB에 닿기까지

매매 코드 따라가기

KIS 소켓에서 바이트가 들어와, 전략이 신호를 내고, 게이트를 지나 주문이 나가고, 체결통보가 원장에 닿고, 저널이 DB로 적재되기까지 64걸음. 걸음마다 파일:줄이 붙어 있다.

KIS OpenAPI
   │  WebSocket 프레임 (H0STCNT0 체결 · H0STASP0 호가 · H0STCNI 체결통보)
   ▼
1  수신 스레드 ×소켓   recv_loop → parse_message → dispatch_record → decode_* → TradeData
   │  push_to(행=수신, 열=샤드)      ← 문자열은 여기서 끝, 종목은 정수 id
   ▼
2  샤드 스레드 ×M      Shard::step → Router::for_each → 전략 on_trade_batch → Emitted
   │  shard_out (MPSC)
   ▼
3  전략(디스패치) 스레드  SignalDispatcher::from_strategy → submit → order_queue
   │  order_queue (SPSC)
   ▼
4  주문 스레드          OrderRateLimiter → OrderRouter::new_route → OrderGate::check
   │                              → on_intent(원장 INTENT 선기록·선점)
   │                              → KisClient::submit_order_acknowledgement
   ▼
KIS 주문 REST  ──ODNO──▶  주문 상태 갱신
   │
   │  체결통보가 WebSocket으로 돌아온다
   ▼
5  체결 스레드          fill_queue → OrderRouter::on_fill → PositionLedger::on_fill_confirmed
   │                              → 원장 CSV · ledger_YYYYMMDD.bin 저널
   ▼
적재                  ledger_recorder.py (저널 읽기) · ZMQ SUB (PUB 수신)
   │
   ▼
TimescaleDB  ──▶  Grafana
수신 샤드·전략 주문 체결 데이터·제어 파이썬·DB
