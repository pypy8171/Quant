# C++ 코드 규약

`Quant/` 아래 C++(와 같은 이름 규칙을 받는 `.py`)의 작성 규약 정본이다. 작성: 2026-09-24.

상위 규약은 C++ Core Guidelines다. 이 문서에는 우리가 고른 것만 적는다. 코드 예시는 `docs/examples/`의 짧은 파일로
링크하고, 그 예시 파일은 ctest 타깃으로 컴파일한다(예정: 폴더는 아직 없다, [../DEFERRED_ISSUES.md](../DEFERRED_ISSUES.md) D-26).

## 0. 읽는 법

**번호 셋은 역할이 다르다.**

| 번호 | 역할 | 예 |
|---|---|---|
| 절 번호 | 규칙의 주소 | 4.1 |
| D-NNN | 그렇게 정한 이유. [../DECISIONS.md](../DECISIONS.md)에 있고, 코드에서는 `[why D-NNN]`으로 가리킨다 | D-092 |
| 검사기 번호 | 규칙을 막는 장치. `../quant-devtools/check_code_conventions.py`의 규칙 번호 | 검사기 7 |

**검사기 번호표.** 이 표는 검사기 파일 머리의 번호와 같게 둔다(예정: 어긋나면 게이트가 `[확인]`을 낸다).

| 번호 | 검사 | 기준 | 판정 |
|---|---|---|---|
| 1 | 중괄호 | Allman, 한 문장 본문도 중괄호, `}` 뒤·제어문 앞 빈 줄 | 오류 |
| 2 | D-NNN 참조 | 코드와 문서의 D-NNN이 [../DECISIONS.md](../DECISIONS.md)에 있는지 | 오류 |
| 3 | 태그 철자 | `[...]` 태그가 10.2의 태그 중 하나인지 | 경고 |
| 4 | C 스타일 캐스트 | `(타입)식` 형태. `(void)x;`는 예외 | 오류 |
| 5 | 불필요한 복사 | json `value(k, json::array())`류 깊은 복사는 오류, 값 range-for는 경고 | 오류·경고 |
| 6 | 줄 성격 집계 | 코드·주석·빈 줄 수. `--comment-only`면 코드 줄 변경이 0이 아닐 때 실패 | 리포트 |
| 7 | 약어 이름 | 새로 붙인 이름이 약어 표에 있거나 한 글자인지. 2.3의 예외 표는 제외 | 오류 |
| 8 | 매직 숫자 | 문자열·주석을 뺀 코드 줄의 세 자리 이상 정수. 3.7의 예외 자리는 제외 | 오류 |
| 9 | 헤더 안 함수 몸통 | 1.5에서 허용한 것 밖의 몸통 | 오류 |

검사기는 추가된 줄만 본다(9번은 이번 변경이 건드린 줄에 걸친 몸통만).

**라벨.** 규칙 뒤에 붙은 라벨은 그 규칙을 실제로 무엇이 막는지를 뜻한다.

| 라벨 | 뜻 |
|---|---|
| (컴파일러) | 빌드가 실패한다(`static_assert` 등) |
| (컴파일러 경고) | 컴파일러가 경고를 낸다. 새 타깃에서는 오류로 처리하고, 기존 타깃은 경고 수를 베이스라인과 비교해 늘어나면 막는다 |
| (게이트 N) | 커밋 직전에 검사기 N번이 막는다 |
| (테스트) | ctest가 실패한다 |
| (tidy) | clang-tidy가 막는다. 게이트에 연결하기 전까지는 리뷰로 본다 |
| (리뷰) | 사람이 본다 |
| (예정: X) | 장치가 아직 없다. 생기면 X가 된다. 그때까지는 리뷰로 본다 |

**기존 위반은 동결한다.** 지금 있는 위반은 `../quant-devtools/` 아래 베이스라인 파일에 적는다. 게이트는 베이스라인
밖에서 새로 생긴 위반만 막는다.

| 종류 | 베이스라인 기준 |
|---|---|
| 코드 | 파일과 줄 |
| 로그 문구 | 파일과 문구 해시 |
| 컴파일러 경고 | 타깃별 개수 |
| hot path 할당 | 함수별 횟수 |
| 락 깊이 | 함수별 최대값 |

**벗어날 때.** 그 줄에 `// [why D-NNN]`과 `NOLINT(검사명)`을 함께 단다. 같은 예외가 세 곳을 넘으면 규칙을 다시 본다.

**현황 수치는 본문에 두지 않는다.** 전환이 얼마나 진행됐는지 같은 수치는 주간 리포트(10.3·10.4)에 싣는다. 이 문서가
바뀐 내용은 커밋 본문에 적는다. 도입 계획은 [../DEFERRED_ISSUES.md](../DEFERRED_ISSUES.md) D-26에 둔다.

## 1. 구조

- **1.1** 파일 머리에는 세 가지를 적는다. (예정: 게이트, 목적 줄과 소유 줄이 있는지 본다)
  - 책임 한 문장
  - 스레드 소유: 어느 메서드를 어느 스레드가 부르는지
  - 관련 D-NNN

  파일을 나누는 기준은 줄 수가 아니라 책임과 샤딩 경계다. 파일이 크게 늘면 게이트는 `[확인]`으로 묻기만 한다.
- **1.2** 전역 가변 상태와 싱글톤은 두지 않는다. 의존성은 생성자로 받는다. (리뷰)
- **1.3** 인터페이스는 구현을 바꿔 끼울 지점에만 둔다. 구현이 하나뿐인 추상 클래스는 만들지 않는다. (리뷰)
  - hot path라도 가상 함수를 금지하지 않는다. 예측이 맞는 가상 호출은 1~3ns라서, 초당 30만 건이어도 1초에 약 1ms다.
  - 템플릿화는 측정으로 병목이 확인된 곳에만 쓴다.
- **1.4** 주석 처리한 코드와 `.bak` 파일은 남기지 않는다. (예정: 게이트, `.bak`만 본다. 주석 처리한 코드는 리뷰)
- **1.5** 헤더에는 선언만 둔다(D-118). (게이트 9)
  - 구현은 같은 이름의 `.cpp`로 옮기고(`Quant/include/risk/ProtectiveOrders.h` → `Quant/src/risk/ProtectiveOrders.cpp`),
    `Quant/CMakeLists.txt`의 `HEADER_IMPL_SOURCES`에 등록한다. 그 목록은 `quant_header_impl` 정적 라이브러리가 되어
    실행 타깃 전부가 건다.
  - 헤더에 남겨도 되는 것은 세 가지다: template·`requires`·`constexpr`·`consteval`·`static_assert`, 분기와 반복이 없는
    5줄 이하 접근자(`int size() const { return count_; }`), 멤버 기본값.
  - 검사기 9는 중괄호 깊이를 따라 함수 몸통만 고르므로 람다·멤버 초기화자·제어문은 걸리지 않는다. `Quant/tests/`·
    `Quant/tools/` 아래 헤더는 보지 않는다(실행 타깃에 안 들어간다).
  - 이유: 헤더에 함수 몸통이 있으면 그 헤더를 include하는 번역 단위마다 다시 컴파일하고, 몸통 한 줄을 고쳐도 그 헤더를
    건드린 파일이 모두 다시 빌드된다.

## 2. 이름

- **2.1** 타입은 `PascalCase`, 함수와 변수는 `snake_case`, 멤버는 `name_`으로 쓴다. (tidy)
- **2.2** 약어와 한 글자 이름을 쓰지 않는다. `qty` 대신 `quantity`, `cfg` 대신 `config`, `it` 대신 `iterator`,
  `ev` 대신 `event`, `sym` 대신 `symbol_id`를 쓰고, `i`·`n`·`x`는 쓰지 않는다. 예외는 템플릿 인자 `T`·`U`뿐이다.
  인덱스에는 무엇을 가리키는지 드러나는 이름을 붙인다. 읽는 사람이 도메인 용어를 코드에서 온전한 말로 매번 만나야
  몸에 붙기 때문이다. 길어지는 것은 감수한다(`moving_average_10`이 `ma10`보다 길다). 경위와 전수 변환 규칙은 D-092. (게이트 7)
- **2.3** 예외는 "약어가 아니라 그 자체로 이름인 것"뿐이다.
  - KIS 전문 필드(`tr_id`·`odno`·`hhmmss`, `[wire]` 줄)
  - 지표 이름(`pnl`, `atr`, `pbr`, `per`, `p50`, `p99`)
  - 단위 접미사(`_ns`, `_us`, `_ms`, `_sec`, `_min`)
  - 표준 라이브러리·OS의 멤버(`std::`·`zmq::` 한정 이름, `.str()`, `.ec`, `tm_min`, `sin_addr`)
  - `argc`·`argv`·`ok`·`now`, 네임스페이스 별칭 `fs`

  판정 표는 리네임에 쓴 `../quant-devtools/rename_maps/01_fields.json`과 `../quant-devtools/rename_frags.py`(FRAG·WHOLE·
  SKIP·WIRE)다. 예외를 늘리려면 그 표의 SKIP·WIRE를 고치고, 그 이름이 외부 명세나 업계 표기에서 왔는지 커밋 본문에
  적는다(예정: 표가 바뀌면 게이트가 `[확인]`을 낸다).
- **2.4** 타입 접두어(`m_p`, `vt`)와 예약 식별자(밑줄+대문자, 이중 밑줄)는 쓰지 않는다. (예정: 게이트)
- **2.5** `.py`도 같은 규칙을 따른다(T-14 ②). 검사기는 줄 정규식이 아니라 `ast`로 그 파일이 이름을 붙이는 자리(변수·
  인자·함수·클래스·import 별칭)만 보므로, f-문자열 접두사·독스트링 본문·남의 라이브러리 멤버(`frame.iloc`)는 걸리지
  않는다. 파이썬 관례로 굳은 이름(`np`·`pd`·`df`·`ax`·`kwargs`·`_`)은 검사기의 `PY_CONVENTION` 집합에 둔다. (게이트 7)

## 3. 식과 모양

- **3.1** 중괄호는 Allman 스타일로 쓴다. 본문이 한 줄이어도 중괄호를 붙인다. `}` 뒤와 제어문 앞에는 빈 줄을 하나 둔다. (게이트 1)
  - 정리는 `py ../quant-devtools/brace_style.py <파일>`로 한다.
  - `brace_style.py`는 clang-format을 부르지 않는 별도 구현이다. `.clang-format`의 `BreakBeforeBraces: Allman`과
    `InsertBraces: true`는 검사기 1과 같은 규칙에 맞춰 둔 설정이다.
  - 편집기가 저장한 결과가 게이트에 걸리면 `.clang-format` 쪽을 고친다. 빈 줄 규칙은 검사기 1만 본다.
- **3.2** 한 문장에는 부수효과를 하나만 둔다. 식 안에서 대입하지 않는다. (tidy)
- **3.3** 중간값은 이름 있는 `const` 지역변수에 담는다. 그래야 디버거와 덤프에서 값이 보인다. (리뷰)
- **3.4** 조회 함수는 `const`로 만든다. 버리면 안 되는 반환값에는 `[[nodiscard]]`를 붙인다. (tidy)
- **3.5** `#ifdef _DEBUG` 블록 안에는 대입과 제어문을 두지 않는다. assert와 로그 호출만 둔다. (예정: 게이트)
- **3.6** 캐스트 (게이트 4)
  - C 스타일 캐스트는 쓰지 않는다. `(void)x;`만 예외다. 한 문법이 static·reinterpret·const 세 가지를 겸해 의도가
    코드에 드러나지 않고, `(int)`처럼 짧아 grep으로 훑을 수도 없다.
  - 값 변환은 `static_cast`로 한다. 값이 잘리거나 부호가 뒤집히는 것은 `static_cast`도 막지 못하니, 범위가 걱정되면
    캐스트 대신 호출 쪽 가드나 `std::cmp_less` 같은 안전 비교를 쓴다.
  - `reinterpret_cast`는 OS API(`sockaddr*`)와 바이트 버퍼(`char*`) 경계에만 쓴다. 전문과 공유 메모리를 해석할 때는
    `memcpy`나 `bit_cast`를 쓴다. 정렬 규칙과 aliasing 규칙을 어기지 않기 위해서다.
  - `const_cast`는 외부 C API 경계에만 쓴다.
- **3.7** 뜻이 있는 숫자는 `constexpr` 상수나 config로 뺀다. `row < 1200`은 아는 사람에게만 20:00이고, 창이 바뀔 때(D-097)
  흩어진 숫자를 하나 놓치면 장중 결함이 된다. (게이트 8)
  - 일반 파일에서는 세 자리 이상의 숫자를 검사한다.
  - 주문·체결·리스크 경로(`risk/`, `ipc/OrderRouter*`, `exchange/`, 원장)에서는 0을 뺀 모든 리터럴을 검사한다. 1은
    `+ 1`·`- 1` 증감 자리에서만 허용한다. (예정: 게이트 8 확장)
  - 예외 자리: `constexpr`·`enum`·`case`·`#define`, 이름에 바로 넣는 초기화(`x = 540;`·`x{540}`), 멤버 기본값,
    `constexpr` 표의 행, json 기본값(`node.value("interval_sec", 300)` — 키가 이름이다), 배열 크기·템플릿 인자·시프트,
    chrono 리터럴(`100ms`), 10의 거듭제곱(단위 환산), 문자열 안, `Quant/tests/`(고정값이 곧 검증 대상).
  - 상수를 두는 곳: 시각은 `Quant/include/core/KstTime.h`의 분 상수, 큐 용량은 `Engine::ShardPipeline`의 상수, 거래소
    규칙은 `Quant/include/core/TickSize.h`의 `constexpr` 표다. 표에는 `[formula]`와 출처를 붙인다.
- **3.8** 다음에는 `noexcept`를 붙인다. (tidy)
  - 이동 생성자, 이동 대입, 소멸자, swap. 이동 생성자가 `noexcept`가 아니면 `vector`가 재할당할 때 이동하지 않고 복사한다.
  - 6.4 목록에 있는 hot path 함수. 예외가 밖으로 새면 그 스레드가 종료된다.
- **3.9** 열거형은 `enum class`로 만든다. 열거형 `switch`에는 `default`를 두지 않고 모든 값을 적는다. 그래야 값이 늘었을 때
  컴파일러가 빠진 곳을 알려 준다. (컴파일러 경고: GCC/Clang `-Wswitch`. MSVC C4062는 예정: 11.1)
- **3.10** 가상 함수를 재정의할 때는 `override`를 붙인다. 더 상속하지 않을 클래스에는 `final`을 붙인다. (예정: 컴파일러 경고,
  11.1과 함께 `-Wsuggest-override`와 MSVC C4263을 켠다)
- **3.11** 헤더는 `#pragma once`를 쓴다. (리뷰)
  - include 순서는 짝 헤더 → 표준 라이브러리 → 외부 라이브러리 → 저장소 헤더다. 블록 사이에는 빈 줄을 둔다.
  - 헤더에서 포인터나 참조로만 쓰는 타입은 전방 선언한다.
  - 예외: 헤더에 남긴 접근자가 값으로 돌려주는 타입과, 멤버로 값을 갖는 타입은 완전한 타입이어야 한다. 이런 타입의
    헤더는 include한다.

## 4. 스레드

- **4.1** 모든 가변 상태에는 소유 스레드가 하나 있다. (예정: 컴파일러 경고, clang)
  - 소유 스레드는 스레드 역할로 선언한다.
  - 멤버에는 `GUARDED_BY(<역할>)`을, 그 멤버를 다루는 함수에는 `REQUIRES(<역할>)`을 붙인다.
  - 스레드 루프 진입점의 첫 줄에서 `<역할>.assert_current()`로 역할을 얻는다.
- **4.2** 스레드 사이로 흘러가는 이벤트는 큐로 넘긴다. 생산자가 하나면 `RingBuffer`, 여럿이면 `MpscQueue`를 쓴다. 큐가
  찼을 때 버릴지 기다릴지는 큐를 만드는 자리에서 정한다. (리뷰)
  - 체결, 주문, 캡처 경로의 이벤트는 유실하지 않는다.
  - 예외: 체결통보 큐(`fill_queue`, [Quant/src/core/Engine.cpp](../../Quant/src/core/Engine.cpp#L884)의 `push_fill`)는
    가득 차면 버린다. 수신 스레드가 기다리면 모든 종목의 틱 수신이 멈추기 때문이다(D-056). 건수는 `fill_dropped`로 센다.
    - 메우는 길: 잔고 대조가 원장과 잔고의 차이를 미체결 주문 이내에서만 맞춘다. 매도는 `absorb_missed_sell`,
      매수는 `absorb_missed_buy`(CODE_REVIEW W-1 전에는 매수를 메우지 않아 재기동 때까지 원장에 없었다).
    - 틀린 수량으로 주문이 나갈 수 있는 창: 버린 때부터 같은 잔고가 두 번 연속 보일 때까지, 곧 잔고 대조 두 주기와
      체결 뒤 대조 유예(`kPostFillDeferSec` 5초, 체결이 이어지면 최대 30초)를 더한 시간이다. 그동안 매수를 버렸으면
      원장이 보유를 적게, 매도를 버렸으면 많게 본다. 증권사가 매도가능수량으로 한 번 더 막으므로 없는 주식을 파는
      주문은 거부로 끝난다.
    - 드물다는 근거: 09-17부터 쌓인 `[큐 고수위]` 2,404줄에서 최고 7/1024, `fill_dropped`는 0이다. 1024가 차려면
      소비 스레드가 멈춰야 하고, 그러면 `check_runtime_health.py`의 체결 큐 행이 잡는다.
    - 버린 건의 원본(가격, 시각, 주문번호)을 복구하는 경로는 아직 없다. 평단은 잔고 평단으로 대신한다
      ([../DEFERRED_ISSUES.md](../DEFERRED_ISSUES.md) D-26의 7).
  - 덮어쓰기는 호가 스냅샷과 표시용 최신값에만 허용한다. 덮어쓴 건수는 센다.
- **4.3** 소비자는 한 번에 비울 건수나 시간 예산을 정해 둔다. 큐 하나가 루프를 독점하지 못하게 하려는 것이다. (리뷰)
- **4.4** 이벤트가 아닌 공유 상태는 아래 셋 중 하나로만 둔다. (예정: 컴파일러 경고, clang)
  - 스냅샷 포인터 교체
  - `std::atomic`: `memory_order`를 명시하고, 그 순서로 충분한 이유를 `[inv]`로 적는다
  - `std::mutex`: 지키는 대상을 `GUARDED_BY`로 선언한다
- **4.5** 락은 RAII로만 잡는다. 락을 쥔 동안에는 I/O, 로그, 콜백 호출, 할당을 하지 않는다. (리뷰)
- **4.6** `recursive_mutex`는 쓰지 않는다. 모든 스레드가 거쳐 가는 전역 락도 두지 않는다. (예정: 게이트, `recursive_mutex`만 본다)
- **4.7** 한 번에 락을 둘 이상 잡지 않는다. 불가피하면 D-NNN으로 근거를 남기고, 경우에 따라 다음 둘 중 하나로 처리한다.
  - **같은 함수 안에서 잡을 때**: `std::scoped_lock`으로 한 번에 잡는다. (예정: 게이트, 여러 락을 받는 `scoped_lock`·
    `std::lock`에 순위 표 참조가 있는지 본다)
  - **함수를 건너 잡을 때**(예: `on_fill` → `on_fill_confirmed` → `journal_append`): 락마다 순위를 등록하고, 순위가
    올라가는 순서로만 잡는다. (예정: 테스트, 4.8)
  - 순위는 코드의 순위 표(`enum class LockLevel`)에 등록한다. `[lock-order]` 주석은 그 표를 가리키기만 한다.
- **4.8** 디버그 빌드에서는 락을 순위 있는 래퍼로 잡는다(예: `DebugMutex history_mutex_{LockLevel::History}`). (예정: 테스트)
  - 래퍼는 지금 쥐고 있는 락의 순위를 `thread_local`로 기억한다.
  - 새로 잡으려는 락의 순위가 지금 쥔 순위보다 낮거나 같으면 스택을 로그로 남긴다.
  - 정해진 시간 안에 락을 잡지 못해도 스택을 남긴다.
  - 디버그 ctest에서 위 두 경우 중 하나라도 나오면 실패로 처리한다.
  - 함수별 최대 락 깊이는 베이스라인에 적고, 늘어난 것만 막는다. `on_fill` 사슬(깊이 3)은 이 베이스라인으로 동결해
    두었다가, 사슬을 풀면 기준을 낮춘다.
- **4.9** 비동기 결과가 돌아오면 포인터가 아니라 id로 대상을 다시 찾는다. (리뷰)
- **4.10** 타이머는 할 일을 큐에 넣기만 하고, 실행은 소유 스레드가 한다. 순회 중에 생긴 추가·삭제는 모아 두었다가 다음
  루프 시작 때 반영한다. (리뷰)

## 5. 공유 메모리

이 절은 `[shm]` 구조체와 그 위에 올린 자료구조에만 적용한다. 이 구역에서는 6.1과 6.2를 적용하지 않는다.

- **5.0** 공유 메모리에 놓이는 구조체에는 `[shm]` 태그를 단다. 이 절의 게이트는 이 태그로 대상을 고른다. 태그가 빠지면
  검사도 통째로 빠지므로, 매핑을 여는 파일(`ipc/`)에서 태그 없이 매핑 주소로 캐스트되는 구조체도 막는다. (예정: 게이트)
- **5.1** 모든 공유 메모리 구조체는 `static_assert`로 `is_standard_layout_v`와 `is_trivially_destructible_v`를 강제한다. (컴파일러)
  - 원자 필드가 없는 데이터 구조체(seqlock 본문, 링 슬롯의 내용)는 `is_trivially_copyable_v`도 강제한다.
  - `std::atomic`은 trivially copyable이 아니다. 그래서 원자 필드를 가진 구조체에는 이 검사를 걸지 않는다.
- **5.2** 포인터 멤버와 참조 멤버를 두지 않는다. 매핑 주소가 프로세스마다 다르기 때문이다. 다른 위치는 오프셋이나
  인덱스로 가리킨다. (예정: 게이트)
- **5.3** 레이아웃은 프로세스 사이의 프로토콜로 다룬다. (컴파일러)
  - 헤더에 매직 넘버, 판 번호, 크기를 두고 기동 때 검사한다. 맞지 않으면 즉시 중단한다.
  - 필드 위치는 `static_assert(offsetof(...))`로 고정한다. 5.5의 워드 배열 본문은 시작 오프셋이 8의 배수인지도 이
    자리에서 검사한다.
  - 정렬은 명시하고, 패딩은 직접 넣는다.
- **5.4** 원자 변수는 `is_always_lock_free`인 타입만 쓴다. (컴파일러)
- **5.5** 프로세스 사이에서 최신값을 공유할 때(하트비트, 장부 사본)는 쓰는 쪽이 하나인 seqlock을 쓴다. 프로세스 간
  뮤텍스는 쓰지 않는다. 락을 쥔 프로세스가 죽으면 그 락을 풀 수 없기 때문이다. (예정: 테스트, 리눅스 TSan 스트레스 테스트)
  - 쓰는 쪽: 번호를 홀수로 저장(relaxed) → `atomic_thread_fence(release)` → 데이터 쓰기 → 번호를 짝수로 저장(release)
  - 읽는 쪽: 번호 읽기(acquire, 홀수면 재시도) → 데이터 복사 → `atomic_thread_fence(acquire)` → 번호 다시 읽기(relaxed,
    처음과 다르면 재시도)
  - 데이터 본문은 trivially copyable 구조체다. 크기는 8의 배수, 정렬은 `alignas(8)`이다.
  - 공유 영역에는 본문을 `uint64_t` 워드 배열로 둔다. 쓰는 쪽과 읽는 쪽 모두 워드마다 `std::atomic_ref<uint64_t>`로
    relaxed 저장·읽기를 한다. 일반 대입과 일반 읽기는 쓰지 않는다.
  - 쓰는 쪽은 구조체를 `memcpy`로 워드에 옮긴 뒤 저장한다. 읽는 쪽은 읽은 워드를 `memcpy`로 구조체에 옮긴다. 공유
    영역을 구조체째 `memcpy`로 직접 읽고 쓰지 않는다.
  - `docs/examples/seqlock.cpp`가 생기면 이 절차의 정본은 그 파일의 주석으로 옮긴다.
- **5.6** 유실하면 안 되는 경로(주문, 체결통보, 캡처)는 seqlock으로 넘기지 않는다. 슬롯마다 시퀀스 번호가 있는 링을
  쓴다. 쓰는 쪽은 빈 슬롯이 없을 때 덮어쓰지 않고, 기다리거나 실패를 알린다. (예정: 테스트, 유실 0 스트레스 테스트)
- **5.7** 상대 프로세스가 살아 있는지는 하트비트 시각으로 판단한다. "데이터가 없음"과 "상대가 죽음"을 구분할 수 있어야
  한다. (리뷰)
- **5.8** 세그먼트를 만드는 쪽과 정리하는 쪽을 주석으로 적는다. 재기동 때 남아 있는 세그먼트는 매직 넘버와 생성 시각으로
  확인한 뒤, 이어받을지 새로 만들지 정한다. (리뷰)
- **5.9** 읽기 인덱스와 쓰기 인덱스는 서로 다른 캐시 라인에 둔다. (컴파일러)
  - 두 인덱스에 각각 `alignas(kCacheLine)`을 붙인다. [Quant/include/core/RingBuffer.h](../../Quant/include/core/RingBuffer.h)와
    같은 방식이다.
  - 링 타입 정의 안에 `static_assert(offsetof(읽기) % kCacheLine == 0 && offsetof(쓰기) % kCacheLine == 0 &&
    offsetof(읽기) != offsetof(쓰기))`를 둔다.
- **5.10** 데이터를 쓴 뒤 인덱스나 표식을 공개하는 저장은 `release`로 한다. 읽는 쪽의 로드는 `acquire`로 한다. 매직 넘버
  같은 표식도 일반 대입으로 쓰지 않는다. 프로세스 안의 큐에도 같은 규칙을 적용한다. (예정: 게이트, `[shm]` 원자 필드에
  메모리 순서를 명시했는지 본다)

## 6. 메모리와 복사

- **6.1** 소유하면 값이나 `unique_ptr`를 쓰고, 빌리면 참조나 `span`·`string_view`를 쓴다. (리뷰)
- **6.2** `new`/`delete`를 직접 쓰지 않는다. (tidy)
- **6.3** 안 해도 되는 복사는 만들지 않는다. 이것은 성능 규칙이 아니라 문법 규칙이다(원칙 7과 부딪히지 않는다). 필요 없는
  복사가 있으면 읽는 사람이 그 이유를 다시 따져야 한다. (게이트 5: json은 오류, 값 range-for는 경고. 나머지는 tidy)
  - 조회 결과는 `const&`나 `string_view`로 돌려준다. 멤버를 그대로 주면 `const std::string&`, 리터럴 폴백이 섞이면
    `std::string_view`다. 뷰를 돌려줄 때는 어느 컨테이너에 수명이 묶이는지 `[inv]`로 적는다(재해시가 뷰를 끊는다).
  - json 노드는 `value(k, json::array())` 대신 `find()`로 참조를 잡는다. 기본값을 만들려고 노드 전체를 베끼기 때문이다.
    없을 때만 함수 지역 `static const`의 빈 노드를 가리킨다.
  - range-for는 `const auto&`로 쓴다. 원소가 trivially copyable이고 16바이트 이하일 때만 값으로 받는다. `SymbolId`와
    `FillKey`가 여기에 해당한다.
  - 값 전달은 sink(`std::move`로 멤버에 넣는 자리)에만 쓴다. 읽기만 하면 `const&`다.
  - 일부러 복사할 때(락 안에서 뜬 스냅샷, 호출자가 나중에 고칠 사본)는 이유를 주석으로 남긴다(예: `KisClient::token()`).
    그래야 다음 사람이 지우지 않는다.
- **6.4** hot path 함수의 정본은 할당 테스트에 적힌 함수 목록이다. 지금은 수신 디코드, 전략의 체결 처리, 게이트 처리
  세 가지다. (예정: 테스트, `operator new`를 가로채 할당 횟수를 센다. 예정: 게이트, `[hot]` 태그가 붙었는데 목록에 없는
  함수를 막는다)
  - 목표는 할당 0이다. 할당 0은 측정한 뒤에 고르는 튜닝이 아니라 기본값이다.
  - 테스트는 두 단계로 켠다.
    1. 함수마다 지금 할당 횟수를 베이스라인으로 적고, 횟수가 늘어나면 실패로 처리한다.
    2. 이벤트 구조체에서 문자열 멤버를 뺀 뒤(예: `OrderSignal`의 `std::string`을 정수 id로 바꾼 뒤), 그 함수의 기준을
       0으로 내린다.
  - `[hot]` 태그는 문서용이다.
- **6.5** 개수가 정해진 것(종목, 계좌)은 고정 배열에 둔다. 개수가 바뀌는 것(주문, 체결, 버퍼)만 풀에 둔다. hot path 밖에는
  풀을 두지 않는다. (리뷰)
- **6.6** 풀은 스레드마다 하나씩 둔다. 반납은 풀을 소유한 스레드에서 한다. 다른 스레드가 다 쓴 객체는 큐를 거쳐 소유
  스레드에 돌려보낸다. (리뷰)
- **6.7** 풀의 용량은 기동 때 정한다. 바닥났을 때의 동작(거부, 또는 경고를 남기고 늘리기)은 풀을 만드는 자리에서 고른다.
  조용히 `nullptr`를 돌려주지 않는다. (리뷰)
- **6.8** 풀 밖으로는 인덱스와 세대 번호로 된 핸들을 준다. 반납할 때 초기화하고, 반납한 칸은 ASan poison으로 표시한다.
  사용량, 최고 수위, 바닥난 횟수를 조회할 수 있게 한다. (리뷰)

## 7. 도메인

- **7.1** 가격, 수량, 금액은 정수로 저장하고 비교한다. (예정: 게이트)
  - 스케일은 시장마다 하나로 고정하고 `TickSize.h` 표에 적는다. 주식은 원 단위(×1), 지수 선물·옵션은 ×100(0.01pt)이다.
  - 호가 단위는 스케일로 쓰지 않고, 검증값으로만 쓴다.
  - 수익률과 지표에는 `double`을 허용한다. 기존의 `double` 가격은 동결한다.
  - 게이트는 새 타입과 `[shm]` 구조체에서 이름에 `price`·`amount`·`quantity`·`cash`·`value_krw`가 들어간
    `double`·`float` 필드를 막는다. 이름을 바꿔 게이트를 피해 가는 것은 리뷰에서 잡는다.
- **7.2** 종목, 전략, 주문, 체결은 기동 때 정수 id로 바꾼다(`symbol::SymbolId`, `strategy_table::StrategyId`, `uint64_t`,
  `fill_key::FillKey`). 그 뒤로는 문자열 키 해시맵(`std::unordered_map<std::string, …>`·`std::unordered_set<std::string>`)을
  쓰지 않는다. 문자열 해시와 비교는 키 길이에 비례한다. 체결 키를 정수로 바꿨을 때 조회 시간이 296ns에서 31ns로
  줄었다(D-112). (리뷰)
  - 입력 자체가 문자열인 경계(config 열거값, REST·WS 응답, 캡처 헤더, 운영단말 cid)는 예외로 두고, 이유를 한 줄 적는다
    (예: `Quant/include/core/FeedMux.h`의 `assign_`, `Quant/include/core/DataPoller.h`의 `rest_seen_`).
- **7.3** 경과 시간은 `steady_clock`으로, 기록과 전문에 남기는 시각은 `system_clock`으로 잰다. 내부 단위는 나노초다. (리뷰)
- **7.4** 주문 경로를 지나는 메시지에는 생성 시각과 식별자를 담는다. 구간별 지연을 나중에 다시 계산할 수 있게 하려는
  것이다. (리뷰)
- **7.5** 금액(가격×수량×승수)은 `int64_t`로 계산한다. (리뷰. 도우미는 단위 테스트로 확인)
  - 곱셈은 한 곳의 도우미에서만 한다. 도우미는 넘침을 검사하고, 넘치면 `std::expected`로 실패를 돌려준다.
  - 도우미는 `noexcept`이고 할당하지 않는다. 6.4의 hot path 목록에 넣을 수 있게 하려는 것이다.
  - 다른 곳에서 가격과 수량을 직접 곱하지 않는다. 합계를 누적할 때도 같은 도우미를 쓴다.

## 8. 초기화와 종료

- **8.1** 엔진 전체의 초기화는 아래 세 목록에만 둔다. 새 초기화가 필요하면 이름 있는 함수로 만들고, 목록에 한 줄을 더한다.
  함수 몸통 중간이나 주기 블록, 콜백의 첫 호출에서 초기화하지 않는다. 순서를 읽는 사람은 이 목록만 보면 된다. (리뷰)

  | 목록 | 맡는 것 |
  |---|---|
  | `Quant/src/main.cpp`의 `main()` | 프로세스 수준(콘솔, 로거, 인자, 설정, 크래시 핸들러, 모드 분기) |
  | `Engine::configure(const AppConfig&)`(`Quant/src/core/EngineConfigure.cpp`) | 설정값을 엔진 세터에 주입 |
  | `Engine::start()` | 엔진 부품(샤드·인증·주문 라우터·원장·전략·피드)의 생성과 연결. 스레드 시작은 목록 맨 끝에 모은다 |

- **8.2** 객체 하나는 `construct` → `wire` → `start` 순서를 거친다. `construct`는 자기 멤버만 만들고, `wire`는 다른 객체와
  연결하고, `start`는 스레드를 시작한다. `construct`에서는 다른 객체를 부르지 않는다. (리뷰)
- **8.3** config.json은 `Quant/src/core/AppConfig.cpp`의 `parse_config()` 한 곳에서만 읽는다. Engine 세터와 모드 함수는
  typed 값만 받는다. 키가 없거나 값이 틀리면 네트워크를 건드리기 전에 예외를 던진다. (리뷰)
  - 유일한 예외는 `Quant/src/strategy/StrategyFactory.cpp`다. 전략 타입마다 파라미터 형식이 달라서, 그 형식은 전략 로더가 갖는다.
  - 새 예외는 D-NNN 없이 만들지 않는다.
- **8.4** 함수 안의 `static` 지역변수는 `constexpr`이나 상수로 초기화되는 값(정수·bool·mutex)에만 쓴다. 람다·생성자로
  채우는 매직 스태틱은 호출마다 초기화 가드를 거치고, 첫 호출이 hot path에 걸리면 그 자리에서 초기화 비용을 낸다.
  컴파일 타임 값은 함수 밖의 `constexpr` 표로 빼고(`WebSocketClient.cpp`의 base64 역표가 그 예), 런타임 입력이 필요하면
  8.1의 목록으로 올린다. (리뷰)
- **8.5** 종료는 시작의 역순으로 한다. 대기에는 시한을 두고, 시한을 넘기면 로그를 남긴다. (리뷰)
- **8.6** 시그널 핸들러(Ctrl-C, SIGTERM)는 `std::atomic<bool>` 종료 플래그 하나만 세운다. 실제 종료는 각 루프가 그
  플래그를 보고 8.5의 역순으로 진행한다. 핸들러 안에서는 로그를 쓰지 않고, 할당하지 않고, 락을 잡지 않는다. (리뷰)

## 9. 오류와 로그

- **9.1** 오류를 알리는 방법 (리뷰)
  - hot path에서 실패하면 `std::expected<T, ErrorCode>`를 돌려준다. 돌려줄 값이 없으면 `ErrorCode`만 돌려준다. 둘 다
    `[[nodiscard]]`를 붙인다.
  - `bool` 반환은 "예/아니오" 질문에만 쓴다.
  - `ErrorCode`는 모듈마다 `enum class` 하나를 둔다.
  - 기동 경로에서는 예외를 쓴다.
  - 이 규칙은 새 함수부터 적용하고, 기존의 `bool`·에러코드 반환은 동결한다. 기존 함수를 바꿀 때는 모듈 단위로 바꾸고,
    기능 수정과 분리한 커밋에 담는다.
- **9.2** 스레드 루프는 가장 바깥에서만 예외를 잡는다. 잡은 예외를 빈 메시지로 삼키지 않는다. (리뷰)
- **9.3** 로그는 `설명 - key(value)` 형식으로 쓰고, 호출 위치는 `std::source_location`으로 붙인다. 문체는
  [../STYLE_GUIDE.md](../STYLE_GUIDE.md)를 따른다. (예정: 게이트)
- **9.4** 크래시 핸들러는 덤프와 스택만 로컬에 남긴다. 네트워크, 할당, 락은 쓰지 않는다. (리뷰)

## 10. 주석

- **10.1** 위치별로 적는 것 (리뷰. 파일 머리는 1.1의 게이트가 본다)

  | 위치 | 적는 것 |
  |---|---|
  | 파일 머리 | 1.1의 세 가지. 목록이나 개수는 적지 않고 정본 위치를 가리킨다(예: "검사 항목과 순서의 정본은 `OrderGate.cpp::check` 하나다") |
  | 함수 위 | 이 함수가 따로 있는 이유, 호출 제약(스레드·락 상태), 실패 시 동작. 절차는 풀어 쓰지 않는다 |
  | 멤버 옆 | 단위와 불변식(`// 원, 장중 갱신`). 경위는 D-NNN으로 보낸다 |
  | 블록 안 | 함정과 뻔하지 않은 결정. 태그 없이 세 줄을 넘으면 함수로 뽑거나 D-NNN으로 보낸다 |

- **10.2** 태그는 일곱 가지다. 줄 수 제한의 예외를 표시하고, 함수로 뽑을 수 없는 지식을 코드 옆에 둔다. (게이트 3, 철자만
  본다. `[shm]`·`[hot]`은 검사기 허용 목록에 넣기 전까지 경고가 난다)

  | 태그 | 적는 것 |
  |---|---|
  | `[inv]` | 불변식 |
  | `[lock-order]` | 락 순서(4.7의 순위 표를 가리킨다)·`memory_order` 근거 |
  | `[wire]` | 외부 프로토콜 필드 인덱스·에러코드 |
  | `[why D-NNN]` | 결정 참조 |
  | `[formula]` | 수식·임계값 유도 |
  | `[shm]` | 공유 메모리에 놓이는 구조체(5.0) |
  | `[hot]` | hot path 함수(6.4, 문서용) |

- **10.3** 주석 밀도는 게이트로 막지 않는다. 주간 리포트에 파일별 밀도와 태그 없는 4줄 이상 연속 주석 블록을 표로 남긴다.
- **10.4** 주석 속 별칭(`MM-1`, `G1`, `C-2`, `B2`, `H-1`)은 먼저 D-NNN 매핑표를 만든다. 그다음 그 파일을 고칠 때마다 별칭을
  D-NNN으로 옮긴다. 대응 항목이 없으면 새로 발번하고 `**상태**: 사후 기록(코드 주석에서 이관)`을 단다. 완료 조건은 grep
  결과 0이다. 남은 파일 수는 주간 리포트에 같이 싣는다.
- **10.5** 주석을 줄일 때(에이전트 포함)는 세 단계를 거친다. (리뷰)
  1. 그 주석이 지금 코드와 맞는지 먼저 확인한다. 틀린 주석을 D-NNN으로 옮기면 오류를 정본으로 올리게 된다.
  2. 지운 줄에 있던 숫자, 식별자, ID(`\d+%`, 날짜, `[A-Z]-?\d+`, `§\d`)가 남은 주석·DECISIONS·대상 문서 중 한 곳에 있는지
     목록으로 보고한다. 없으면 지우지 않는다.
  3. 코드 줄 diff는 0이어야 하고(`git diff -U0`에서 `//`·`*`가 없는 삭제·추가 줄 0, 검사기 6의 `--comment-only`), 이 커밋은
     기능 수정 커밋과 분리한다.

## 11. 빌드와 도구

- **11.1** 경고 옵션
  - 현재 옵션: GCC/Clang은 `-Wall -Wextra -Wpedantic -Wno-interference-size`, MSVC는 `/utf-8`뿐이다. (컴파일러 경고)
  - 목표 옵션: MSVC에 `/W4 /permissive-`를, GCC/Clang에 `-Wshadow -Wconversion -Wsuggest-override`를 더한다. 옵션을 켜기
    전에 타깃별 경고 수를 베이스라인에 적는다. (예정: 컴파일러 경고)
  - 경고를 전역으로 끄지 않는다. 새 타깃은 경고를 오류로 처리한다. 이 두 가지는 지금부터 적용한다. (리뷰)
- **11.2** Linux Debug 빌드에는 TSan과 ASan 설정이 이미 있다(한 번에 하나만 켠다). 아직 머지 조건은 아니다. 목표는
  lock-free 자료구조와 공유 메모리 코드가 이 테스트를 통과해야만 머지되게 하는 것이다. (테스트 있음. 머지 조건은 예정)
- **11.3** clang 빌드를 하나 두고 4.1과 4.4의 스레드 안전 검사를 돌린다. (예정: 컴파일러 경고, clang 프리셋을 추가한 뒤)
