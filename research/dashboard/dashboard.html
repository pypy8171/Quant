읽는 법 · 규율

  • 계열 분리 — 계열 B(지수 오버레이)는 종목 포트폴리오(계열 A)와 직접 비교 불가. 표를 계열·벤치마크로 나눈 이유.
  • CAGR·Calmar가 1차 — 창 길이가 다르면(예 98년 vs 30년) 총수익%는 복리로 부풀어 직접 비교 불가. 연환산한 CAGR%·Calmar를 먼저 보고, 총수익%(raw)는 참고로 둔다.
  • 초과CAGR(막대) = 전략 CAGR − Buy&Hold CAGR(%p). 0 중심 바, +초록/−빨강. 그룹 최대치로 스케일.
  • 정직성·비고 — ⚠에 마우스=편향/해석 주의(생존편향·비참여·소표본·수정주가). 표 아래 비고에 전문.
  • 맥락필수 라벨 — regime-ON 비참여(현금)처럼 헤드라인 숫자가 오독을 부르는 행. 초록 '견고'와 구분.
  • 홀드아웃 배너 — 학습구간 Calmar + → 2022 − 전환(표본외 붕괴). 예뻐 보인 지표가 지우면 안 되는 사실.

  • BUG08-20(33)과 08-21(0)의 차이는 시작 시점 슬롯 여유에서 옴. 국면·게이트 때문이 아님
05

패널 이견 · 검증 한계

주요 이견

손실한도 미로깅 성격구현 쪽은 P2(발동 대상 없음), 전략·리스크 쪽은 P0(집행 배선 없음)으로 갈렸다. 결론은 집행 배선 P0 격상(IMP-03).
H0STCNI0 미배선설계대로이긴 하나 사이징 무결성이 깨진다(093190 7.58M > 캡 7.5M). 결론은 정공법 P1(IMP-08), 캡 클램프 선행(IMP-06).
게이팅이 수익을 막는가전략 쪽 교정: 08-21 halt는 옳았다(세션 +31,184 마감). 결론은 결함이 진입컷·사이징 쪽이라는 것.

모의계좌의 한계

모의계좌는 당일 매수분을 당일 매도할 수 없어(익일 반영) DevScale·ITB의 전제인 EOD net-flat을 forward-test 할 수 없다.

08-20 청산 실패는 전략 결함과 모의계좌 특성이 뒤섞여 분리하기 어렵다. 청산 안정성 근거는 모의 EOD에서 취하지 않고, 강제청산 대체 경로는 실계좌 이관 전 조건으로만 요구한다(IMP-11).

06

개선안

손실통제, 청산 배관, 관측성, 전략 재배치 순

P0실계좌 전환 게이트 — 닫히기 전 라이브 금지3건 · 벽시계·워치독·집행
IMP-01리스크M

EOD 청산·손실컷을 시세 이벤트에서 떼어 독립 벽시계 타이머로 구동

EOD가 on_trade_batch(td 도착)로만 트리거되고, td는 data_thread_fn이 공급한다. 크래시나 12002 정체가 나면 EOD가 돌지 않는다. 08-20·08-21 이월의 공통 원인이다.

control_thread_fn에 kst_hhmm≥eod 감시 가디언을 두고, 시세와 무관하게 청산 시그널을 order_queue_에 직접 push한다. 전략 EOD 블록은 백업으로 남긴다.

IMP-02관측성M

크래시 관측성(SEH를 C++ 예외로 변환) + 외부 워치독 자동 재기동

12:57:07에 증상 없이 종료됐고 [ERROR]는 0건이다. 접근위반(SEH)은 /EHsc의 catch(std::exception)이 못 잡는다.

스레드 시작부에 _set_se_translator 또는 __try/__except를 두어 폴트 주소·스택을 남긴다. 외부 워치독이 exe 종료를 감지해 재기동하고, 부트스트랩 재시드 후 EOD 가디언이 청산한다.

IMP-03리스크M

손실한도 −300k 집행 배선 (신규 BUY 차단 + soft de-risk + 세션 진입예산)

OrderGate 손실한도가 신규 BUY에만 적용되고 강제청산·kill로 넘어가는 단계가 없다. −317,260 시점에 차단도 경고도 없었다.

daily_pnl_ ≤ −300k이면 WARN 1회 + 기존 set_entry_halt() 재사용(신규 BUY 차단, SELL/CANCEL 통과) + 청산 모드로 EOD 가디언 경로 연결. −180k 선제 soft halt.

P1청산 배관 정합 · 관측성 · 전략 재배치8건
IMP-04리스크M

EOD 강제청산 에스컬레이션 상태머신

sellable 상태를 {N / 잠김 / 미상}으로 구분하고 marketable-limit 대체 경로를 둔다. 12002 실패가 잠김으로 보이는 것을 없애고, 15:20까지 미청산이면 심각 알림을 낸다.

IMP-05버그수정M

취소 후 매도로 넘어가는 순차 상태머신

CANCELLING→취소확인 대기→REQUERY→LIQUIDATING. read-before-cancel 레이스를 없앤다(최소수정은 1-tick 지연 플래그).

IMP-06리스크M

확정잔고 기반 종목 명목 캡 클램프

reserved_ 드리프트로 093190이 7.58M으로 캡 7.5M을 넘었다. 리컨사일 확정잔고 명목이 캡 이상이면 신규 BUY를 거부한다. IMP-08 전에 바로 쓸 수 있는 방어다.

IMP-07리스크S

manage_holdings eod 1600을 1515로 정렬

protect-only 1600이 캐리오버를 장중에 청산하지 않아 018260·161390이 2박 이월됐다. DevScale 본체 eod와 시각을 맞춘다.

IMP-08버그수정L

H0STCNI0 체결통보 배선 / FILLED 전이

ACCEPTED에서 벗어나지 못해 오래된 주문이 취소무시 64건을 냈다. 체결통보 웹소켓을 따로 배선하거나 reconcile로 on_fill 상태전이를 만든다.

IMP-09버그수정S

Logger localtime 스레드안전 수정

std::localtime을 lock 밖에서 호출해 4스레드 데이터레이스(UB)가 있다. localtime_s/r로 바꾸고 포맷을 lock 안으로 옮긴다.

IMP-10관측성M

관측 모니터 예외격리 + 리컨사일 우선 처리

수급·섹터·매크로가 data_thread에서 순차 실행돼 청산·손실컷이 낡은 스냅샷 위에서 판단한다. try/catch로 격리하고 리컨사일을 먼저 돌린다.

IMP-11전략M

DevScale INTRADAY 실계좌 보류 + H7 우선

모의 EOD로는 검증할 수 없다고 STRATEGY_LAB에 명시돼 있다. 실계좌 라이브는 보류하고, 백테스트 가능한 H7(dip-buy EOD ablation, 2022 홀드아웃 사전등록)로 옮긴다.

P2저비용 구조 방어 — 파라미터 튜닝 금지2건
IMP-12전략S

entry_halt 히스테리시스(dwell + 확인카운터)

−3 임계에서 5회 났던 진동을 억제한다. 최소 15분 dwell과 2연속 폴 확인 후 전환. regime 3-state 재설계는 보류목록에 둔다.

IMP-13리스크S

사다리 회전 상한 가드

종목당 세션 재호가·누적체결 명목 상한을 둔다(IMP-06과 공유). 값 튜닝 없이 구조적 상한만으로 093190 같은 반복 재주문을 통제한다.
