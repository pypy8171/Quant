## 4. 문제·진단 (심각도 순)

### (1) 엔진 크래시 — 공유 KisClient 토큰 데이터 레이스 [해결]
11:03 세션이 로그 중간 truncate와 함께 사망. 조사 결과 분봉 500 파싱 경로는 **완전히 보호돼 있었고**(비던지기 파서 + 스레드 예외격리), 진짜 원인은 **전략·데이터 두 스레드가 같은 `quote_kis_` 인스턴스를 뮤텍스 없이 공유**하는 것. 토큰 재발급 순간 `authenticate()`가 `std::string access_token_`를 재기록하는 동안 다른 스레드가 Bearer 헤더로 그 문자열을 복사 → **use-after-free/힙 손상 → segfault**(로그 truncate와 부합). → `token_mtx_`로 직렬화, `authenticate_locked()` 분리(데드락 방지), `ensure_authenticated` double-checked, 헤더 조립 23곳 `token()`(락 하 복사본)으로 치환.

### (2) 모의 잔고조회 매 사이클 타임아웃(12002) — 리컨사일 사망 [해결]
오후 14:40부터 `inquire-balance`(openavts:29443)가 매 폴링 GET 3회 전부 `ReceiveResponse 실패: 12002`(WinHTTP 타임아웃). 결과: **리컨사일이 조용히 no-op** → `reserved_` wipe·손실컷·포지션 재시드 전부 미작동, 재시도로 **사이클당 ~60초 낭비**(데이터 스레드 정체, 존 판정 주기 ~88s로 늘어남). 서버측 지연이라 응답을 빠르게 할 순 없어 **리컨사일 서킷브레이커**(연속 실패 시 지수 백오프 1·2·4·8 사이클로 조회 자체 스킵, 성공 시 즉시 복귀)로 핫루프 보호.

### (3) `reserved_` 누수 수정(#1)이 실제 미배포였음 [해결]
이전 세션 요약엔 "완료"로 적혔으나 grep 0건 — OrderGate.h 선언·OrderGate.cpp 정의·on_cancel 하드닝·Engine 호출부 **전부 디스크에 없었음**. 체결피드(H0STCNI0) 부재로 `reserved_`가 영구 누적(H-1 드리프트) → check()가 positions_+reserved_로 한도를 봐 정상 신호까지 과잉 차단. → `reset_reserved()` 신규 구현 + 리컨사일 성공 사이클마다 호출(서버 확정 스냅샷 기준 선점 비움) + on_cancel 음수/과잉해제 가드.

### (4) 명목캡 상단 절단 — 08-13에서 지속 [정책 확인 필요]
`종목당 명목 한도 초과` 거부 4건(`15053500 > 7500000` 005180, `8374080 > 7500000` 073240). 이미 포지션이 쌓인 종목에서 추가 사다리 발을 7.5M 캡이 차단 — 백스톱 의도대로 동작하나 **사다리 완성을 상단에서 자르는** 구조. 사고는 아니나 캡과 사다리 사이징 정책의 정합성 재확인 필요.

### (5) KIS 실도메인 HTTP 500 폭풍 — 만성 [방어 중]
시세 조회(inquire-price/time·daily-itemchartprice) 500건+. GET 멱등 재시도로 흡수되나 발주 RTT 지연. 신규 이슈 아님, 재시도 상한/선형 백오프로 억제 중.
